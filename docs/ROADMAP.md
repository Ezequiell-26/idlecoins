# Roadmap

## Phase 0 — Foundation

- repository structure
- product documentation
- dual-ledger model
- security principles
- CI
- minimal shared contracts

## Phase 1 — Playable MVP

- registration/auth
- game dashboard
- clicking
- passive production
- upgrades
- offline progression
- missions
- daily reward
- persistence

## Phase 2 — Rewards

- provider adapter interface
- rewarded-ad game boosts
- offer/task adapter
- pending rewards
- validation callbacks
- earn history

## Phase 3 — Wallet

- authoritative ledger
- payout eligibility
- withdrawal requests
- payout provider abstraction
- reconciliation
- admin review

## Phase 4 — Trust

- anti-fraud scoring
- rate limits
- duplicate detection
- payout risk rules
- audit tooling
- account controls

## Phase 5 — Growth

- referrals
- seasons
- events
- achievements
- leaderboards
- analytics
- localization

## Definition of Done for money

A money feature is not considered complete until:
- provider validation works
- idempotency is tested
- ledger entries are transactional
- reversal behavior exists
- fraud handling exists
- reconciliation exists
- audit history exists
